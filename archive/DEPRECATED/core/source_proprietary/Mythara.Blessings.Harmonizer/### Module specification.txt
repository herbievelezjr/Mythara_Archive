### Module specification

**Name:** mythara.blessings.harmonizer  
**Purpose:** deterministic clause harmonization engine that scores, normalizes, and selects clauses for downstream Perception and Renderer layers while enforcing safety thresholds, provenance, and audit metadata.  
**Language:** Python 3.10+ (portable, testable, minimal C extensions)  
**Deliverables:** module package, CLI, canonical config, unit + integration tests, determinism harness, manifest entry, README_ESCROW.md excerpt.

---

### Public API (high-level)

- class **Harmonizer(config: HarmonizerConfig)**  
  - method **score_candidates(observables: dict, candidates: List[ClauseProposal]) -> List[RankedCandidate]**  
  - method **select_candidate(ranked: List[RankedCandidate], seed: int|None) -> SelectionResult**  
  - method **apply_safety_filters(ranked: List[RankedCandidate], sanitizer_flags: List[str], leakage_flags: List[str]) -> FilterResult**  
  - method **canonicalize_output(selection: SelectionResult) -> CanonicalRenderHint**  
  - method **to_audit_record(selection: SelectionResult, metadata: dict) -> dict**

- dataclasses: **ClauseProposal**, **RankedCandidate**, **SelectionResult**, **FilterResult**, **HarmonizerConfig**

- functions: **compute_harmonization_score(proposal, observables, config)**, **canonicalize_json(obj)**, **fingerprint(obj)**

---

### Core behavior & rules

- Score is in [0.0, 1.0] combining: clause.base_score, observables.confidence, harmonization_status weight, locale_match bonus/penalty, and penalty for harmonization_delta > config.harmonization_delta_cutoff.  
- Safety-first: if sanitizer_flags or leakage_flags contain high/critical IDs, selection must return null primary candidate and a deterministic resolver_hint (fallback id) in SelectionResult.  
- Determinism: given same inputs + seed, selection must be identical. Tie-breaker: lexical clause_id unless determinism_seed provided (use seeded RNG deterministic ordering).  
- Provenance: every output must include manifest_ref, prompt_hash, determinism_seed (or null), and computed deterministic_fingerprint = sha256(canonicalized_output + sorted_metadata).  
- Latency target: aim for < 50 ms median in production profile; implement fast-path scoring with cached precomputed clause features.  
- Audit: Harmonizer must log its audit record (to audit_chain writer passed via dependency injection) before returning selection.

### Implementation notes & pitfalls

- Canonicalization: use JSON with sorted keys, no insignificant whitespace, and deterministic serialization for fingerprinting.  
- Caching: precompute clause static features (locale tags, base_score) to meet latency. Invalidate on fallback_catalog updates.  
- Safety mapping: maintain rule severity mapping in config so numeric thresholds map to low/medium/high/critical consistently.  
- Audit-write atomicity: harmonizer should prepare audit record and call injected writer that guarantees atomic append and returns stored_record_id before returning selection.  
- Human-review flow: surface explainability_snippet and human_review_reason when substitution rate or human_review_threshold exceeded.
