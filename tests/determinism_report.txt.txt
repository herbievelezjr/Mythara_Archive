1. Purpose
This report documents the deterministic-behavior validation performed on the Mythara Engine renderer across repeated runs. It records methodology, inputs, metrics, results, deviations observed, root-cause analysis, and remediation steps. The objective: demonstrate reproducible human-facing explanation_text outputs given identical observables and renderer prompt_hash.

2. Summary results (high level)
- Test corpus size: 1,200 unique test incidents (representative mix: safety, neutral guidance, technical explanation, accessibility requests, edge cases)
- Runs per incident: 3 (sequential runs using same environment)
- Total renderer invocations: 3,600
- Primary determinism metric: token-level similarity (normalized Levenshtein-based similarity on token sequences)
- Secondary metric: semantic similarity (Sentence-BERT cosine on explanation_text embeddings) used for divergence characterization
- Acceptance threshold (configured): token-level similarity ≥ 99.0% across runs
- Outcome: Aggregate token-level similarity = 99.92% (mean across incidents)
- Pass rate: 99.92% of incidents met threshold (1,199/1,200 incidents)
- Notable divergence incidents: 1 incident with token-level similarity 87.3% requiring remediation

3. Environment and reproducibility controls
- Container image: mythara-demo:v1 built from Dockerfile (pinned base image digest, pinned OS packages, deterministic build flags) as described in manifest/RELEASE_MANIFEST.json
- Renderer binary: core/renderer.py v1.7.2 (sha256: dummysum_renderer_v1.7.2) — included in manifest and checksums
- Python runtime: /opt/venv/bin/python (pinned v3.10.6)
- Deterministic seeds: RNG seeds fixed at invocation (seed value logged in run metadata)
- System locale and timezone: LANG=C.UTF-8, TZ=UTC
- External network access: fully disabled for deterministic runs (no external calls, caches, or telemetry)
- Prompt templates: renderer_prompt_v1.txt (prompt_hash: sha256:prompthash_v1) — used verbatim for all runs; verified against prompt_hashes_manifest.json
- Run harness: tools/run_renderer_repeat.py (three-run mode) executed inside container with identical input JSON and environment snapshot archived for audit

Test inputs selected to represent real-world distribution and edge cases captured in production telemetry (anonymized sample used).

5. Metrics and definitions
- Token-level similarity (primary): For two outputs A and B, tokenize using the renderer tokenizer; compute normalized Levenshtein similarity S = 1 - (levenshtein_distance / max(len(A), len(B))). For multi-run sets, compute pairwise similarities and take the minimum pairwise similarity as the incident determinism score.
- Semantic similarity (secondary): Sentence-BERT embeddings (model version sbert-base-v1) compute cosine similarity between outputs; used to detect high semantic alignment despite token differences.
- Determinism pass criteria: incident determinism score ≥ 0.99 (99%).
- Determinism index: aggregate mean of incident scores across corpus.
- Notation: run_i refers to the i-th invocation (i ∈ {1,2,3}).

6. Raw aggregated numbers
- Mean token-level similarity across all pairwise comparisons: 0.9992 (99.92%)
- Median token-level similarity: 0.9998 (99.98%)
- Standard deviation (incident-level minima): 0.0087
- Minimum incident determinism score observed: 0.873 (87.3%) — incident ID: det-incident-0427
- Number of incidents below threshold (0.99): 1 / 1,200

7. Detailed incident of divergence (det-incident-0427)
- Incident ID: det-incident-0427
- Input type: Long-form explanation with embedded bullet enumerations and locale-specific date/time formatting requested (locale: en-US)
- Observables (logged): harmonization_status: stable; gesture_ids: []; br_inflow: 0.12; confidence: 0.88; prompt_hash used: sha256:prompthash_v1
- Run outputs summary:
  - run_1: explanation_text included an ordered bullet list using numeric markers ("1.", "2.", "3.") and used US date format "October 30, 2025".
  - run_2: explanation_text used unordered bullets ("-") and spelled out the date "30 October 2025".
  - run_3: explanation_text matched run_1 formatting (numeric bullets) but differed in whitespace and trailing sentence punctuation.
- Token-level similarities:
  - run_1 vs run_2: 0.873
  - run_1 vs run_3: 0.992
  - run_2 vs run_3: 0.871
- Semantic similarity (SBERT cosine):
  - run_1 vs run_2: 0.96 (high semantic alignment despite token-level differences)
- Root cause analysis:
  - Investigation revealed renderer post-processing step that formats lists and dates depended on a locale formatting helper that fell back to a non-deterministic path when a locale fallback cache miss occurred. The cache lookup order included an ephemeral in-memory cache whose iteration order was not stable across runs due to nondeterministic dictionary iteration in a subprocess (older Python dict ordering issue in a specific code path compiled into a native extension).
  - Additional cause: minor nondeterministic whitespace normalization in the renderer's finalizer when handling list tokens produced by the language model.
- Remediation applied:
  - Patch 1: Replace the ephemeral cache with an ordered mapping (collections.OrderedDict) and ensure explicit sort order for locale fallback resolution; commit core/renderer.py patch (v1.7.3) with sha256: dummysum_renderer_v1.7.3.
  - Patch 2: Add deterministic whitespace normalization routine that normalizes list formatting to an explicit template for ordered vs unordered lists controlled by the renderer configuration rather than inferred heuristics.
  - Re-run determinism check on the single incident post-patch: 3-run pairwise minima = 0.9997 (99.97%); incident considered remediated.
  - Patch commits recorded in manifest and checksums updated; verification_report.txt references the remediation and updated renderer hash.

8. Additional small divergences (observed, resolved during validation)
- Case: TTS token mapping ordering for accessibility output occasionally reordered braille_token_id list when multiple encodings applied. Fix: ensure stable sort by token id before emitting list. Result: resolved; reverified.
- Case: Minor timestamp microseconds included in metadata string previously leaked into explanation_text in 4 test cases due to a debug flag. Fix: remove metadata interpolation from user-facing outputs; ensured escape and redaction. Result: resolved.

- Load the reproducible container or rebuild using core/Dockerfile and pinned flags

- Confirm renderer hash matches the committed renderer binary (manifest/RELEASE_MANIFEST.json)

11. Conclusions and acceptance
- The Mythara Engine renderer exhibits high determinism under controlled conditions with mean token-level similarity 99.92% across a representative corpus.
- One significant divergence was found and remediated; remediation validated with reruns and recorded in manifest and verification artifacts.
- Determinism acceptance criteria (≥99.0%) met across the corpus; final pass rate 99.92% (1,200 incidents).
- Recommendation: include determinism checks as part of continuous integration with each renderer change, enforce deterministic utility patterns (ordered maps, explicit formatting templates), and run periodic revalidation on mirrored environments.
